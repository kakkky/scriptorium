::::details connect.go の実装
```go:app/infrastructure/db/connect.go
package db

import (
	"context"
	"database/sql"
	"fmt"
	"log"
	"time"

	_ "github.com/go-sql-driver/mysql"
	"github.com/kakkky/app/config"
)

// パッケージ変数としてDB接続を管理
var (
	db *sql.DB
)

// パッケージ変数として*sql.DBをセット
func SetDB(d *sql.DB) {
	db = d
}

func GetDB() *sql.DB {
	return db
}

// DBをに接続する
func NewDB(ctx context.Context, cfg *config.Config) func() {
	db, close, err := connect(
		ctx,
		cfg.MySQL.User,
		cfg.MySQL.Password,
		cfg.MySQL.Host,
		cfg.MySQL.Port,
		cfg.MySQL.Name,
	)
	if err != nil {
		// DB接続失敗は復旧不可
		panic(err)
	}
	// dbパッケージ変数にセット
	SetDB(db)
	return close
}

const (
	maxRetriesCount = 5
	initialDelay    = 5 * time.Second
)
// DBへ接続
// 失敗したらリトライさせ、待機時間を2倍ずつ指数的に増やす(エクスポネンシャルバックオフ)
func connect(ctx context.Context, user, password, host, port, name string) (*sql.DB, func(), error) {
	delay := initialDelay
	for i := 0; i < maxRetriesCount; i++ {
		dsn := fmt.Sprintf("%s:%s@tcp(%s:%s)/%s?parseTime=true", user, password, host, port, name)
		db, err := sql.Open("mysql", dsn)
		if err != nil {
			// DB接続の初期エラーが発生した場合のログ
			log.Printf("failed to open db (attempt %d/%d): %v", i+1, maxRetriesCount, err)
		} else {
			// 接続確認
			if err := db.PingContext(ctx); err == nil {
				// 成功した場合、呼び出し元でdb.Close()を実行できるようにする
				log.Printf("successfully connected to db (attempt %d/%d)", i+1, maxRetriesCount)
				return db, func() { db.Close() }, nil
			} else {
				// 接続できた場合のエラーメッセージ
				log.Printf("failed to ping db: %v", err)
			}
		}

		// 接続できなかったらリトライ
		log.Printf("failed to connect to db (attempt %d/%d), retrying in %v seconds...", i+1, maxRetriesCount, delay/time.Second)
		time.Sleep(delay)
		// 待機時間を２倍
		delay *= 2
	}

	// 最大試行回数を超えても接続できなかった場合
	return nil, nil, fmt.Errorf("failed to connect to db after %d attempts", maxRetriesCount)
}

```

### `NewDB()`の実装
main関数から呼び出すことになるこの関数の実装のポイントを見ていきます。
```go
// DBをに接続する
func NewDB(ctx context.Context, cfg *config.Config) func() {
	db, close, err := connect(
		ctx,
		cfg.MySQL.User,
		cfg.MySQL.Password,
		cfg.MySQL.Host,
		cfg.MySQL.Port,
		cfg.MySQL.Name,
	)
	if err != nil {
		// DB接続失敗は復旧不可
		panic(err)
	}
	// dbパッケージ変数にセット
	SetDB(db)
	return close
}
```
#### `Config`の使用
引数にて`*config.Config`型の`cfg`を受け取っています。
実際に接続を行う`connect()`関数に接続情報を渡すために、埋め込み型である`MySQL`構造体から各環境変数を取得し渡しています。
なお、`connect()`にて、以下のように接続情報が使用されています。
```go
dsn := fmt.Sprintf("%s:%s@tcp(%s:%s)/%s?parseTime=true", user, password, host, port, name)
		db, err := sql.Open("mysql", dsn)
```
#### `*sql.DB`をパッケージ変数で管理
`connect()`はdb接続情報である`*sql.DB`を返します。
それを、`SetDB()`関数によってパッケージ変数にセットしているのがわかります。
```go
	db, close, err := connect(
		// 省略
	)
	// 省略
	// dbパッケージ変数にセット
	SetDB(db)
```
ゲッター関数も用意しています。
```go
// パッケージ変数としてDB接続を管理
var (
	db *sql.DB
)

// パッケージ変数として*sql.DBをセット
func SetDB(d *sql.DB) {
	db = d
}

func GetDB() *sql.DB {
	return db
}
```
この`*sql.DB`インスタンスは、次章で設定するormでも参照します。また、テスト環境でも、「テスト環境のDB接続情報」として参照します。基本どこからでも参照できるように、このような設計としています。

### エクスポネンシャルバックオフを用いた接続処理
`connect()`関数の具体的な実装ですが、簡単に処理の流れを表すと以下のようになっています。

1. DBに接続するための環境変数を受け取り、コンテナ内に起動しているDBに接続（`sql.Open()`）
    - エラーがあれば一定時間待機して(`time.Sleep(delay)`)、再トライ
2. 接続確認を行う(`db.PingContext(ctx)`)
    - エラーがない（接続OK）ならば、`*sql.DB`インスタンスとdb接続をクローズする関数を返す
    - エラーがあれば一定時間待機して(`time.Sleep(delay)`)、再トライ
3. 最大試行回数の5回（`maxRetriesCount`）を超えてしまった場合、エラー（接続失敗）を返す


一回の接続失敗でシステムが落ちてしまっては困るため、５回まで再トライさせるようにしています。
そして、その再トライまでにインターバルを設け、失敗を重ねるごとにその時間を2倍して伸ばすようにしています。
これを、**エクスポネンシャルバックオフ**といいます。
::::message
#### エクスポネンシャルバックオフ
これは、リトライ処理の際に、再試行の間隔を指数関数的に増加させる手法のことです。
何度も等間隔にリトライしないことでシステムの負荷を軽減する目的があります。
今回の実装だと、
```
1回目: 5秒
2回目: 10秒
3回目: 20秒
4回目: 40秒
5回目: 80秒
```
と増えていきます。５回目の80秒はやり過ぎ感あるのですが。
手法と目的だけ理解できればOKです。
::::

## DBマイグレーション
DBにおけるマイグレーションとは、DBのテーブルなどの変更をファイルに記録して、その内容を実行しDBのスキーマ(テーブル、インデックス、カラムの追加・変更・削除など)を更新することです。
https://qiita.com/to3izo/items/7b8d44021cb386de2ef7

単に、`todo-db`コンテナに入って、`alter table .....`と打ったりして直接スキーマを変更していくこともできますが、それだとDBスキーマの変更を追いづらいです。
そこで、「マイグレーションファイル」に変更内容や作成したテーブルの内容を記録することで、データベースのスキーマをバージョン管理します。これにより、開発環境や本番環境でのスキーマ変更を簡単に追跡・管理でき、スキーマの変更が一貫性を持って行われます。

スキーマの再現性も確保されるため、開発環境のDBの状態をテスト環境にそのまま再現することができます。

このようにマイグレーションはとても便利です。

golangにおけるマイグレーションの方法はいくつかありますが、今回は`golang-migrate`というツールを使います。

https://github.com/golang-migrate/migrate

https://github.com/golang-migrate/migrate/tree/master/cmd/migrate

これはCLIツールです。
インストールは`Dockerfile.app`にてすでに行っています。
```Dockerfile
RUN go install -tags 'mysql' github.com/golang-migrate/migrate/v4/cmd/migrate@latest
```
早速、テーブル作成を行ってみましょう。
### go-migrateの使い方（CLI）
以下の流れでマイグレーションは進めます。

1. マイグレーションファイルを作成
2.  マイグレーションをup(変更を適用してスキーマを更新)する内容とdown(変更内容をロールバックする=戻す)する内容を記述
3.  マイグレーションをup(変更を適用)

#### マイグレーションファイル作成
以下のコマンドでファイルを生成します。
```
migrate create -ext <拡張子> -dir <出力先> -seq <マイグレーションファイル名>
```
例えば、`xxxxxxxxx.up.sql`と`xxxxxxxx.down.sql`の二つが作成されます。

Makefileには以下のタスクを定義しています。
```Makefile
# マイグレーションファイルを作成
# コマンド例: $ make migrate-create name=<migration-name>
migrate-create:
	$(eval NAME=$(or $(name),$(error "Error: Please specify a migration name using name=<name>")))
	@echo "Creating migration file..."
	cd app/ && migrate create -ext sql -dir $(MIGRATE_PATH) -seq $(NAME)
```
いちいちマイグレーションファイルの出力先を入力するのは面倒なので定数として定義しています。
```Makefile
MIGRATE_PATH = infrastructure/db/migrations
```
#### マイグレーションファイルに記述
`xxxxxxxxx.up.sql`と`xxxxxxxx.down.sql`に記述します。

`xxxxxxxxx.up.sql`には、適用させたい変更をSQLで記述します。
テーブルが作りたいのであれば、`create table ....`などと書きます。
`xxxxxxxx.down.sql`には、upした内容を取り消す（ロールバック）内容を記述します。
upに`create table`と書いたなら、`drop table ...`でテーブルを削除する内容を書きます。

#### マイグレーションを適用
`-verbose`フラグは、コマンドを実行後、マイグレーションを適用させる様子をロギングするためのものです。
```
$ migrate --path <参照するマイグレーションファイルのパス> --database <DBサーバーのURL> -verbose up
```
Makefileには以下のタスクが定義してあります。
```Makefile
# マイグレーションを適用
# コマンド例: $ make migrate-up
migrate-up:
	@echo "Applying migrations..."
	docker compose run --rm app migrate --path $(MIGRATE_PATH) --database "$(DB_URL)" -verbose up

# マイグレーションをロールバック
# コマンド例: $ make migrate-down
migrate-down:
	@echo "Rolling back migrations..."
	docker compose run --rm app migrate --path $(MIGRATE_PATH) --database "$(DB_URL)" -verbose down
```
DB_URLは、定数として定義しています。
```Makefile
DB_URL = mysql://user:pswd@tcp(db:3306)/todo-db?parseTime=true
```
また、`docker compose run --rm app`というふうに、一時的にコンテナを起動させてコンテナ内で`migrate`コマンドを実行しています。
こうしているのは、DBサーバーが起動していないとDBのスキーマ変更が不可能だからです。

`--rm`オプションを付加しているので、実行後コンテナは削除されます。

::::message
#### マイグレーションに失敗した時
SQLの構文エラーなどが原因で、マイグレーションを`up`することに失敗した場合、SQLを修正して`up`しなおしたとしても以下のようなエラーが出る可能性があります。
```
error: Dirty database version 3. Fix and force version.
make: *** [migrate-up] Error 1
```
その場合は、最後のバージョンを指定してdirtyなバージョンをリセットしましょう。
例えば、`000004_create_tasks_table.up`といったファイルのマイグレーションが失敗したとしましょう。このマイグレーションのバージョンは「4」となります。この場合、バージョン4がdirty versionとしてみなされます。そこで、`migrate force 3`とコマンドをうち、バージョンを3（失敗する前の状態）に強制変更してあげます。すると、問題なく再度マイグレーションを`up`できると思います。
Makefileには以下のようにタスクを定義してあります。
```Makefile
# マイグレーションのバージョンをセット
# migration-upが失敗した時は、最後のバージョンにforceしなおしてから再度upするようにする
# コマンド例: $ make migrate-force version=<version_number>
migrate-force:
	@echo "Forcing database migration version to $(version)..."
	docker compose run --rm app migrate --path $(MIGRATE_PATH) --database "$(DB_URL)" force $(version)
```

::::details redis_client.go の実装
```go:app/infrastructure/kvs/redis_client.go
package kvs

import (
	"context"
	"fmt"
	"log"
	"time"

	"github.com/kakkky/app/config"
	"github.com/redis/go-redis/v9"
)

var redisClient *redis.Client

// パッケージ変数を取得
func GetRedisClient() *redis.Client {
	return redisClient
}

func NewRedisClient(ctx context.Context, cfg *config.Config) *redis.Client {
	// Redisクライアントを作成
	redisClient = redis.NewClient(&redis.Options{
		Addr:         fmt.Sprintf("%s:%s", cfg.Redis.Host, cfg.Redis.Port),
		ReadTimeout:  3 * time.Second,
		WriteTimeout: 3 * time.Second,
		// contextによるタイムアウトを許可
		ContextTimeoutEnabled: true,
	})

	// Redisが接続できるか確認するため、pingコマンドを実行
	_, err := redisClient.Ping(ctx).Result()
	if err != nil {
		log.Fatalf("failed to connect to redis: %v", err)
	} else {
		log.Println("successfully connected to redis")
	}

	return redisClient
}
```
::::
ポイントは以下の通りです。
- `Config`を受け取っている
- `*redis.Client`型のインスタンス（接続情報）をパッケージ変数にセットしている

基本的にはDBへの接続の時と変わりません。

### `Config`を受け取っている
接続のために環境変数を取得しています。
```go
	// Redisクライアントを作成
	redisClient = redis.NewClient(&redis.Options{
		Addr:         fmt.Sprintf("%s:%s", cfg.Redis.Host, cfg.Redis.Port),
		ReadTimeout:  3 * time.Second,
		WriteTimeout: 3 * time.Second,
		// contextによるタイムアウトを許可
		ContextTimeoutEnabled: true,
	})
```
### 接続情報をパッケージ変数で管理する
`redisClient`をパッケージ変数として定義しています。
リポジトリでは、`GetRedisClient`関数で取得した`*redis.Client`型のインスタンスを利用して操作します。
```go
var redisClient *redis.Client

// パッケージ変数を取得
func GetRedisClient() *redis.Client {
	return redisClient
}

func NewRedisClient(ctx context.Context, cfg *config.Config) *redis.Client {
    // 代入している
	redisClient = redis.NewClient(&redis.Options{
		// 省略
	})
    // 省略
	return redisClient
}
```
また、帰り値としても`*redis.Client`を返していますが、これは`main()`にてRedisクライアントをクローズさせるためです。

# main関数で呼び出す
MySQLへの接続、Redisへの接続を実装したので、mainパッケージの`main()`関数にて呼び出しましょう。

```go:app/main.go
package main

import (
	"context"
	"log"

	"github.com/kakkky/app/config"
	"github.com/kakkky/app/infrastructure/db"
	"github.com/kakkky/app/infrastructure/kvs"
)

func main() {
	ctx := context.Background()
	cfg, err := config.NewConfig()
	if err != nil {
		log.Fatalf("failed to read config : %v", err)
	}
	run(ctx, cfg)
}

func run(ctx context.Context, cfg *config.Config) {
	// データベース接続を初期化し、終了時にクローズする
	close := db.NewDB(ctx, cfg)
	defer close()

	// Redisクライアントに接続
	redisClient := kvs.NewRedisClient(ctx, cfg)
	defer redisClient.Close()
}
```

これで、goプログラムを起動するとMySQL、Redisに接続されるようになりました。
