# 環境変数
第7章では、インフラストラクチャ層で MySQL と Redis に接続します。MySQL と Redis、およびアプリケーションサーバーはすべて Docker コンテナ内で「起動」している状態です。しかし、アプリケーションがそれらに「接続」するには、Docker Compose ファイル (compose.yml) に定義された環境変数を仕様する必要があります。

以下は`app`コンテナの`environment`部分のみを抜粋したものです。
```yml
    environment:
      PORT: ":8080"
      TODO_DB_HOST: db
      TODO_DB_PORT: 3306
      TODO_DB_USER: user
      TODO_DB_PASSWORD: pswd
      TODO_DB_NAME: todo-db
      TODO_KVS_HOST: kvs
      TODO_KVS_PORT: 6379
```

これらをアプリケーション内で効率的に管理するためには、サードパーティのパッケージを使うと便利です。
今回は以下のパッケージを使用します。

https://github.com/kelseyhightower/envconfig

以下のコマンドを打って、インストールしておいてください。
```
make get-app name="github.com/kelseyhightower/envconfig"
```

# 実装する
## Configの実装・テスト
早速実装に取り掛かりましょう。
`app`ディレクトリに`/config`ディレクトリを作成してください。

```go:app/config/config.go
package config

import "github.com/kelseyhightower/envconfig"

type Config struct {
	Server server
	MySQL  mysql
	Redis  redis
}

type server struct {
	Port string `envconfig:"PORT"`
}

type mysql struct {
	Name     string `envconfig:"TODO_DB_NAME"`
	User     string `envconfig:"TODO_DB_USER"`
	Password string `envconfig:"TODO_DB_PASSWORD"`
	Port     string `envconfig:"TODO_DB_PORT"`
	Host     string `envconfig:"TODO_DB_HOST"`
}

type redis struct {
	Host string `envconfig:"TODO_KVS_HOST"`
	Port string `envconfig:"TODO_KVS_PORT"`
}

func NewConfig() (*Config, error) {
	var cfg Config
	if err := envconfig.Process("", &cfg); err != nil {
		return nil, err
	}
	return &cfg, nil
}
```
`Config`構造体のみ公開しており、`server`、`mysql`、`redis`構造体を埋め込んでいます。
`envconfig`というタグをフィールドに付加することで、設定している環境変数を読み込み、構造体にマッピングしてくれます。

`NewConfig()`関数は`Config`構造体を返すものです。

きちんと環境変数を読み込めているかを確かめるテストも書いておきます。
```go:app/config/config_test.go
package config

import "testing"

func TestInitConfig(t *testing.T) {
	tests := []struct {
		name    string
		want    string
		setEnv  string
		wantErr bool
	}{
		{
			name:    "正常系ーADDRESS環境変数を読み込める",
			want:    ":8081",
			setEnv:  ":8081",
			wantErr: false,
		},
	}

	for _, tt := range tests {
		tt := tt
		t.Run(tt.name, func(t *testing.T) {
			t.Setenv("PORT", tt.setEnv)
			cfg, err := NewConfig()
			got := cfg.Server.Port

			if (err != nil) != tt.wantErr {
				t.Errorf("want error : %v ,but : %v", tt.wantErr, err)
			}

			if got != tt.want {
				t.Errorf("want %v , but got : %v", tt.want, got)
			}
		})
	}

}

```
`t.Setenv`メソッドによって、テスト実行中のみ環境変数を設定することができます。

テストでは、`PORT`というキーに`":8081"`という環境変数を設定してそれを`Config`構造体に埋め込まれた`server`構造体の中の`Port`フィールドから取得できるかを検証しています。

## main関数で`Config`を利用する
アプリケーションの起動時に`Config`構造体を初期化し、データベースやキーバリューストアの接続処理を行う関数などに環境変数を渡すようにします。

`main`パッケージに定義する`main()`関数は、実行後、一番初めに呼び出されるものであり、プログラムのエントリーポイントとなります。

https://recursionist.io/learn/languages/go/others/package

```go:app/main.go
package main

import (
	"context"
	"log"

	"github.com/kakkky/app/config"
)

func main() {
	ctx := context.Background()
    // 環境変数を読み込む
	cfg, err := config.NewConfig()
	if err != nil {
		log.Fatalf("failed to read config : %v", err)
	}
    // 環境変数を渡す
	run(ctx, cfg)
}
// run関数の中でさまざまな接続処理を行う（中身は未実装）
func run(ctx context.Context, cfg *config.Config) {
    // DB接続
    // Redis接続
    // HTTPサーバー起動
}

```

`main()`関数の中で`config.NewConfig()`関数を呼び出し、環境変数を読み込んでいます。それを`cfg`変数として`run()`関数に渡しています。

`run()`関数の中では、DB接続、Redis接続、HTTPサーバー起動などインフラストラクチャのレイヤーの処理をいくつか呼び出します。この`cfg`は`run()`関数内で呼び出される接続処理の際に使用していきます。
